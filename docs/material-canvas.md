# 素材画布

普通工作流定义计算，素材桩定义持久化边界，Canvas Inputs / Outputs 定义卡片界面。
这些都是普通 ComfyUI 节点；只有保存为 Canvas 卡片时才校验完整性。不需要 Nodes 2.0。

## 开始使用

1. Turing Utils → 新建 Canvas 卡片。先保存当前工作流，因为这会替换编辑器内容。
   起始工作流只有两个端点与 Image / Video / Audio / Text 四个素材桩，已经连接好。
   也可直接从普通右键菜单创建节点，无需专门的绑定命令。
2. 删除不用的素材桩和对应端口，加入自己的普通计算节点。
3. 从内部输入插槽反向拖线到 Canvas Inputs 尾部的“＋”创建输入；把输出拖到
   Canvas Outputs 的“＋”创建输出。连接类型和初始名称自动确定。
4. 双击端口名称改名；拖动名称排序，插槽圆点用于连线，节点标题用于整体移动。
   排序有让位动画，Esc 取消。右键可删除端口或设置输入的未连接默认值。
5. 保存为 Canvas 卡片。一个桩须同时连接 Inputs 的 position 口和 Outputs 的实际内容口；
   输出端点只能导出桩的内容。未绑定或错误导出会明确报错。
6. 打开素材画布，在项目选择框浏览服务器 output 目录，打开或新建项目。
7. 画布右键“添加节点”，选择基础图片、视频、音频、文本，或自己保存的卡片。
   “添加节点”按钮使用同一个选择器。
8. 导入素材、编辑文本或选择历史；点击某一素材区域的“执行到这里”更新这一处内容。
   上游已保存素材不会重算，缺少上游素材会报错。

拖动空白区域平移，滚轮缩放。视频默认只显示封面，点击播放才请求媒体；
同页只保留一个播放器，移出视口或隐藏页面后释放，不自动循环。

## 素材节点

- Text：普通 STRING，可手工编辑或接入 value。接入 value 时优先使用输入。
  文本不生成文件，没有 prefix、asset、工作目录参数，也没有文件历史列表。
- Image：加载本实例 input/output 内的图片，或透传 value。
- Audio：加载音频，或透传 value。
- Video：未接 images 时加载文件；接入 images 时按官方 Create Video 创建 VIDEO。
  fps、可选 audio、bit_depth、color_space、codec 使用官方语义；不提供 include_audio。
  VIDEO 需要拆成帧/音频时使用原生视频组件拆分节点，不将 VIDEO 冒充 IMAGE。
- 媒体节点可拖入文件或点击导入，普通编辑器上传到 input；画布导入则拷贝到项目素材目录。
- 计算输入优先于选中的文件。普通队列不自动发布画布素材；没有项目也能使用这些节点。

start/end 不是工作流参数，不进入模板或项目文件。画布的起点秒/终点秒只作为当前页面的
临时选择，0 终点表示素材末尾；执行时快照传递给下游。换素材、切项目或刷新页面会重置。
它不会改写原文件，也不是时间轴编辑器。

## 编辑与保存

- 编辑 Canvas 卡片…：从卡片库打开模板；保存时明确确认覆盖，已有画布实例不变。
- 画布节点的“编辑工作流”：打开该实例的独立副本，当前文本和媒体文件回填。
- 保存回 Canvas 卡片：只更新当前实例，不修改模板或其他实例。
- 普通 ComfyUI 保存仍属于普通 workflow，不等于保存回卡片。

库文件和实例文件均为普通 workflow JSON。保存使用文件版本校验，防止另一个标签页
覆盖新版本；已连接的端口必须先断开才能删除或换类型。端口/桩身份独立于显示名称与顺序。
复制桩后重复身份会报错；不要用相同身份代表不同内容。

## 存储位置

```text
user/<用户>/canvas_cards/<名称>.json    # 卡片库
output/<项目目录>/
  canvas.json                         # 布局、连接、内联文本、选中素材及版本
  cards/<实例 UUID>/workflow.json      # 普通工作流副本
  workspace.sqlite3                   # 媒体索引与执行记录
  materials/image/...
  materials/video/...
  materials/audio/...
```

Text 默认值在 workflow 内，画布当前文本在 canvas.json 内。空字符串也是有效内容。
旧项目的文本选择可读取迁移成内联字符串，不删除旧文本文件。
旧 IMAGE/AUDIO 双输出的视频卡片会提示重新编辑连线，不静默改变类型。
协议保存版本为 2；支持读取不含旧视频协议的版本 1 卡片。
模板 API key 建议使用 Chat 已有的 $ENV_NAME 语义，不保存明文密钥。

## 执行和缓存

使用原生 /prompt 队列和 WebSocket，不增加推理引擎。执行从目标桩追溯到上一个已保存桩；
普通中间结果重新计算，模型/LoRA/Attention 的正常缓存保留，相同配置可复用。
任务结束和失败仅清理本次中间结果，不全局 reset，不复制另一份权重。
原生缓存淘汰、显存卸载和手动释放仍有效，不承诺模型永久驻留。

生成成功自动选中结果；执行期间手工修改内容时不覆盖手工选择。媒体结果仍进入历史，
Text 不建立文件历史。文本使用版本校验和短延迟保存，关闭页面时有未保存草稿会提醒。

## 验证边界

回归覆盖经典界面、原生嵌套子图、端口重排/保存重开、文本局部执行、实例隔离、
文件 Range 播放和千卡片按需挂载。只挂载视口附近卡片，缩小后仅挂载标题；
元数据仍随项目加载，不意味着无限内存或任意规模的性能保证。
